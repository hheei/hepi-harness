# Domain Docs

This is a single-context repository.

Read `GLOSSARY.md` and the ADRs under `docs/adr/` that govern the area before working in it. Use glossary terms in specs, tickets, tests, and implementation notes. Resolve a missing or contested term through `domain-modeling` rather than silently introducing a synonym.

Create numbered ADRs under `docs/adr/` only for decisions that are hard to reverse, surprising without context, and the result of a real trade-off.
