### 已交付瓶颈修复，历史测量仅作注明版本的证据

- SSE 30s 默认注释心跳，避免 quiet stream 被 idle timeout 拆掉；旧 submit-stall 的 300s BodyTimeoutError 不是当前未修复事实。
- 多 terminal tabs 共一条流。连接预算在 completion-delivery.ts 推导：6 个 HTTP/1.1 连接，1 selected、2 headroom、terminal mounted 时再占1，余2 background；无 terminal 时余3 background。历史 browser fixture 从6条流导致 read >3000ms，降至4条流、read 3ms。
- resourceSnapshot 将逐文件串行 RPC 改为一次 host 往返；它并不消除主机本身遍历目录的耗时。
- SSH filesystem 每(profile,root)常驻 session，安装/执行共享 ControlMaster；历史 sshd fixture 验证安装+执行认证7→1。生产使用local transport，这些 SSH 数字不是生产提速测量。

### 剩余限制与待测项

1. **超大纯文本没有 read block**：thinking/images 有按需读块，text tool result 仍整体携带。FRAME_TARGET_BYTES=512KiB 为软目标，FRAME_LIMIT_BYTES=960KiB 为帧硬预算；超预算明确 frame_too_large，可能阻碍会话窗口读取，entry 本身仍可按 id 读取。应以真实大 read/bash 输出场景评估优先级，不能误写为“500KB 硬限制”。[history-window.ts](../../apps/server/src/history-window.ts)
2. **大量资源树仍需扫描**：snapshot 16MiB/20,000 entries 有界，超限拒绝而不自动分页；首次读取慢磁盘/远程目录仍可能等待。前端有发送即 staged/preparing 投影，不存在已证实的“完全无 pending UI”缺陷。[useAgentSession.ts](../../packages/ui/src/hooks/useAgentSession.ts)
3. **Search 有界顺序扫描，无全局索引**：500 sessions、30 results、3s、每会话16MiB；达到边界会 truncated。规模变大可能结果不完整，当前未测出应引入索引的瓶颈。[session-search.ts](../../apps/server/src/session-search.ts)
4. **主动加载历史的浏览器成本**：传输窗口有界，但用户请求的旧页要保留；大量加载后的内存/长任务/渲染未在本次测量。cache 自身有8 sessions/32MiB/10min限制，不能声称无界 cache。[session-view-cache.ts](../../packages/ui/src/lib/session-view-cache.ts)
5. **未知模型 metadata/费用仍是占位**：unknown cost 可能低估花费，contextWindow/maxTokens 占位可能过送或少用能力；这是模型配置准确性限制，不是已测性能回归。[providers.md](../../docs/providers.md)
6. **线上收益未确认**：部署记录停留在2026-10-13 cb4494b/backend+workstation Web+gateway，oracle Web另在df24b7c；当前探针失败，不能把该记录当实时状态，也不能断言线上已包含全部perf tickets。
